# 榫卯结构拆解图鉴

面向传统木作学习者与家具设计人员的纯前端单页应用。项目把榫卯类型、构件尺寸、配合公差、拆装步骤、内联 SVG 示意图与适用家具整理为一套可查询、可编排、可追溯的本地图鉴，所有数据均保存在当前浏览器中。

## Docker 一键启动

```bash
cp .env.example .env && docker compose up -d --build
```

服务启动后访问：`http://localhost:21804`

停止服务：

```bash
docker compose down
```

## 数据存储说明

应用使用 IndexedDB，数据库封装库为 Dexie 4，库名为 `gbmortise-db`。

- `version(1)`：建立 `joints`、`members`、`steps`、`diagrams`、`furniture` 五张表及查询索引。
- `version(2)`：执行升级迁移，为五张表回填 `schemaRev = 2` 字段。
- `version(3)`：新增 `proofDrafts`（校样草稿）与 `catalogVersions`（版本摘要）两张表，并为家具说明回填关键构件引用 `memberId`，供断链校验使用。
- 首次创建数据库时通过 Dexie `populate` 回调写入榫卯、构件、步骤、内联 SVG 与家具关联的种子数据。
- 校样台的四类内容编辑只写入 `proofDrafts` 沙箱；提交通过断链闸门后，在同一个 Dexie 事务内整包替换五张正式表并追加一条 `catalogVersions`，任一步失败整体回滚。
- 原有详情、步序、绘制台页面仍实时写回 IndexedDB；校样台提交时若发现正式表已被这些页面改动，会以正式版本为准拦截并要求重整草稿。

## 核心功能与路由表

| 路由 | 页面 | 核心功能 |
| --- | --- | --- |
| `/` | 入口重定向 | 自动进入榫卯图鉴 |
| `/joints` | 榫卯图鉴总览 | 按家族与难度分组，新建类型，显示构件数与步骤数，导出全部数据 |
| `/joints/:id` | 类型详情 | 查看尺寸表、公差校验、适用家具与步骤；导出当前类型 |
| `/joints/:id/steps` | 拆装步序编排 | 原生拖拽调序并落库，逐步预览内联 SVG 与风险提醒 |
| `/joints/:id/diagram` | 示意图绘制台 | 点击热区回填构件，编辑构件名称、尺寸与 SVG 源 |
| `/furniture` | 家具榫卯反查 | 按家具聚合使用部位与承力说明，新建家具关联 |
| `/proof` | 拆装校样台 | 从榫卯类型建草稿，沙箱内改构件尺寸/步序/示意图/家具说明；尺寸变化重算公差与受影响项；提交前三道断链闸门；原子入库并留版本摘要，可回看、恢复 |

## 拆装校样台工作流

构件尺寸、步序、示意图、家具说明过去分别编辑、直接覆盖正式图鉴。校样台把四类内容收进同一份草稿：

1. **建草稿**：从 `/proof` 选择榫卯类型，按正式当前快照深拷贝生成草稿，记录基线版本号与校验和；编辑只写 `proofDrafts`，不动五张正式表。
2. **改四类内容**：构件尺寸（改尺寸自动按短边重算公差，并标出受影响的榫头/榫眼配合间隙）、拆装步序（增删/调序/编辑）、示意图（绑步序、SVG 热区、登记热区）、家具说明（部位、承力、引用构件）。
3. **提交核对（断链整批拦住）**：
   - 每步步序都必须绑定一张示意图，图绑定的步序必须仍存在；
   - SVG 内联热区 `data-member-id` 与登记热区都必须回链到草稿内现有构件；
   - 家具说明必须引用现有构件作为受力依据。
   任一 error 未清，提交按钮整体不可用，服务层在事务内再核一次，半批也不进正式图鉴；warning（公差带、空文案、序号不连续）不拦截。
4. **原子入库**：五张正式表（该榫卯域先删后写）+ `catalogVersions` 版本摘要 + 草稿状态在同一个 Dexie 读写事务内完成。事务内比较正式快照校验和与草稿基线：正式已被别处直写即判定冲突，**冲突以正式版本为准**，提交拒绝，可用“以正式版本为准重整草稿”重建。
5. **写失败可恢复继续提交**：若正式图鉴写失败（页面提供“演练写失败/回滚”按钮），事务整体回滚、正式表零改动，草稿标记 `failed` 且内容完整保留，修复后可直接再次提交。
6. **版本回看与恢复**：每次入库留版本摘要（四类内容变更计数、校验和、来源草稿/恢复自版本）。恢复历史版本前重跑断链闸门；若正式已有更新版本，不直接覆盖，改为据旧版本生成一份新校样草稿（冲突以正式为准）；恢复最新版本则原子回滚并新增一条“恢复自 vN”的版本摘要。

```bash
cd frontend
npm run test:proof       # 校样台端到端：断链拦截/写失败回滚/原子入库/恢复重核/冲突（fake-indexeddb）
npm run test:migration   # Dexie v2 → v3 升级迁移
npm run build            # tsc 类型检查 + Vite 生产构建
```
